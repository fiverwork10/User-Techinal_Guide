FAST-FOODSX User Guide

A friendly, step-by-step guide for customers, admins, and delivery partners. No technical knowledge needed — just follow along. 😊

1 Getting Started

🌐 Opening the website

1
Open your browser (Chrome, Edge, Firefox).
2
Go to: http://localhost:3000
3
You'll see the homepage with the animated intro, trending dishes, and the full menu below.
💡 If the site doesn't load, make sure the backend server is also running (see the Technical Guide for setup).

👤 Creating an account

1
Click "Sign Up / Register" in the top menu.
2
Fill in your name, email, phone (optional), and a password (at least 6 characters).
3
Type the password again to confirm.
4
Click Register — you're now logged in automatically! 🎉

🔑 Logging in

1
Click "Login" in the top menu.
2
Enter your email and password.
3
Click Login.
  • Regular customers → go to the homepage.
  • Admin accounts → go to the Admin Panel.

🔐 Forgot your password?

1
On the login page, click "Forgot Password".
2
Enter your email and click Send OTP.
3
Check your email for a 6-digit code.
4
Enter the code, choose a new password, click Reset.
5
Log in with your new password.

2 For Customers — How to Order Food

🍽️ Browsing the menu

  • Click "Dishes / Menu" in the top menu to see all food items.
  • Use the search box to find a dish by name.
  • Use filters to narrow by: Category · Price range · Availability · Rating
  • Use Sort by price (low→high / high→low), rating, or newest.
  • Click "Load More" at the bottom to see more dishes.

📖 Viewing a dish

Click any dish to open its detail page, where you can see:

🖼️ Pictures of the dish
📝 Full description
📏 Sizes (pick one to change the price)
🌶️ Spice level & toppings
🔢 Quantity (+ / − buttons)
💬 Special instructions (e.g., "no onions")
⭐ Rating and customer reviews

🛒 Adding to cart & your cart

1
On a dish card or dish page, click "Add to Cart".
2
The cart icon in the top menu shows the total number of items.
3

In the cart page you can change quantities, remove items, clear the whole cart, and see the summary: Subtotal · Delivery Fee · Tax · Total.

💡 Good to know: Delivery is free for orders above $500. Otherwise a delivery fee of $40 applies.

💳 Checkout (paying for your order)

1
Click "Proceed to Checkout".
2
Fill in contact details (name, email, phone) and the delivery address — or click "Use My Current Location".
3

  • Cash on Delivery 💵 — pay when your food arrives
  • Card 💳 — card number, expiry, CVV
  • UPI 📱 — your UPI ID
4
Add a coupon code if you have one.
5
Add any special instructions.
6
Click Place Order and watch the success screen with your order number. 🎉

4 Coins, Vouchers & Rewards

🪙 What are Coins?

Coins are a loyalty reward. Earn them, then spend them to get discounts.

How to earn coins:

  • 🛒 Place orders — earn 1 coin for every $100 spent
  • ✨ Tap "Collect" on dish cards to earn bonus coins
  • 🎁 Special promotions (birthday bonuses, referrals)

How to use coins: look for dishes with a coin discount badge and click "Use Coins".

🎟️ What are Vouchers?

Vouchers are special offers like Free Delivery or % off your order.

  • Earn a free-delivery voucher for every 20 completed orders.
  • Collect vouchers by tapping "Collect" on special dishes.
  • In Coins & Vouchers, click "Use Now", then place your order — the discount is applied at checkout.
⚠️ Vouchers have an expiry date — use them before they expire!

1 What is Fast-FoodsX?

Fast-FoodsX is a complete online food ordering and delivery web application — like a smaller version of Swiggy, Zomato, or DoorDash.

Simple analogy:
🎨 The frontend is the waiter who takes your order and shows you the menu.
⚙️ The backend is the kitchen where the food is prepared, plus the ledger where every order is recorded.
🗄️ The database is the storehouse where all information is kept safe.
PartFolderWhat it does
🎨 Frontendfrontend/The website the customer sees (menu, cart, checkout, login, admin panel).
⚙️ Backendbackend/The brain & engine — stores data, checks logins, processes orders, talks to the database.

Features this app has

👤 User registration & login (with OTP password reset)
🍕 Menu / Dishes (search, filter, sort, details)
🛒 Shopping cart (variations, instructions)
💳 Checkout & payments (COD, card, UPI)
🚚 Order tracking & delivery management
🏷️ Coupons, deals & offers
🪙 Coins & vouchers (loyalty program)
💬 Real-time customer↔admin chat
⭐ Reviews & ratings with admin approval
📊 Admin dashboard with charts & reports
🔔 In-app notifications
👷 Rider / delivery partner registration

🔄 How a request travels (Step by Step)

Let's follow what happens when a user clicks "Add to Cart":

1
Browser (Frontend) — the React page calls a function in a service file (frontend/src/services/cart.service.js).
2
Service — uses Axios to send POST http://localhost:5000/api/cart/add with the dish ID, quantity, and the user's token.
3
Router — the request arrives at server.js, which forwards it to cart.routes.js.
4
Middleware — protect reads the token to confirm the user is logged in.
5
Controller — cart.controller.js → addToCart contains the business logic.
6
Model — uses the Mongoose Model (Cart.js) to read/save data in MongoDB.
7
Response — sends back JSON ({ success: true, cart: {...} }).
8
Back to the Browser — React updates the screen (cart badge count changes).
💡 Same pattern for every feature: Page/Component → Service → Route → Middleware → Controller → Model → Database.

"Emergency room" — converts any error into a friendly JSON response with the right status code.

Anti-spam: apiLimiter 200/min, authLimiter 30/min, coinLimiter 100/min.
upload.js
Multer image uploads saved to uploads/; only image types allowed, 5MB limit.
validation.js
Runs express-validator rules and returns errors if data is invalid.

7 How the Main Features Work

🧾 User Login

1
User opens /login (Login.js).
2
Formik validates email/password.
3
auth.service.login() → POST /api/auth/login.
4
auth.controller.login() finds user, checks password (bcrypt), returns a JWT token.
5
Frontend saves token in localStorage, dispatches loginSuccess.
6
From now on api.js adds Authorization: Bearer <token> to every request.

🛒 Add to Cart

1
User clicks "Add to Cart" on a dish card (DishCard.js).
2
cartSlice.addToCart() → cart.service.addToCartBackend().
3
cart.controller.addToCart() finds the dish, adds/merges the item, recalculates the total.
4
Redux updates the cart; the Navbar badge updates instantly.

📦 Place an Order

1
User fills the checkout form (Checkout.js) and submits.
2
order.service.createOrder() → POST /api/orders.
3
order.controller.createOrder() reads the cart, calculates subtotal + delivery fee (free over $500, else $40) + tax (5%) − discount, creates the Order, deletes the cart.
4
Frontend records payment, emits socket events, clears the cart, shows success screen.

🚚 Order Status & Live Updates

1
Admin changes status → PUT /api/orders/:id/status.
2
updateOrderStatus() updates the order, creates a notification, emits Socket.IO events.
3
The customer's dashboard updates live — no page refresh.

💬 Customer ↔ Admin Chat

1
Both connect via Socket.IO and join a shared chat room.
2
The send-message handler saves the message in the Chat model and delivers it instantly.
3
Online status, typing, and read receipts all work over the socket.

🪙 Coins & Vouchers (Loyalty)

1
Earn 1 coin per $100 spent (coins.controller.earnCoinsForOrder).
2
Tap "Collect" on dish cards for bonus coins (CollectButton.jsx).
3
Every 20 completed orders earns a free-delivery voucher.
4
Coins are spent on dishes with a "coin discount" (applyCoinsToDish).
5
The wallet page (VouchersAndCoins.js) shows balance, history, vouchers.

⭐ Reviews & Ratings

1
User adds a review on DishDetail.js → POST /api/reviews/add.
2
review.controller.addReview() saves it as pending and recomputes the dish's average rating (approved only).
3
Admin approves/rejects in ManageReviews.js → PUT /api/admin/reviews/:id.
4
Only approved reviews appear publicly.

9 How to Add a New Feature

💡 This is the most important part for a developer. Every feature has the same 5 layers — add your code in this order.
1. MODEL (backend) → "how the data looks"
2. CONTROLLER (backend) → "the logic"
3. ROUTE (backend) → "the URL"
4. SERVICE (frontend) → "the messenger"
5. COMPONENT (frontend) → "the screen"

📝 Example: Add a "Favorites" feature

Step 1 — Backend Model (backend/src/models/Favorite.js)

jsconst mongoose = require('mongoose');
const favoriteSchema = new mongoose.Schema({
  user: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true },
  dish: { type: mongoose.Schema.Types.ObjectId, ref: 'Dish', required: true },
  createdAt: { type: Date, default: Date.now }
});
module.exports = mongoose.model('Favorite', favoriteSchema);

Step 2 — Backend Controller (backend/src/controllers/favorite.controller.js)

jsconst Favorite = require('../models/Favorite');
exports.addFavorite = async (req, res) => {
  try {
    const favorite = await Favorite.create({ user: req.user.id, dish: req.body.dishId });
    res.status(201).json({ success: true, favorite });
  } catch (error) {
    res.status(500).json({ success: false, message: error.message });
  }
};
// ... add removeFavorite, getFavorites

Step 3 — Backend Route (backend/src/routes/favorite.routes.js)

jsconst router = require('express').Router();
const { protect } = require('../middleware/auth');
const { addFavorite, removeFavorite, getFavorites } = require('../controllers/favorite.controller');
router.use(protect);                 // only logged-in users
router.post('/', addFavorite);
router.delete('/:dishId', removeFavorite);
router.get('/', getFavorites);
module.exports = router;

Then register the route in backend/server.js:

jsconst favoriteRoutes = require('./src/routes/favorite.routes');
app.use('/api/favorites', favoriteRoutes);

Step 4 — Frontend Service (frontend/src/services/favorite.service.js)

jsimport api from './api';
export const addFavorite = (dishId) => api.post('/favorites', { dishId });
export const removeFavorite = (dishId) => api.delete(`/favorites/${dishId}`);
export const getFavorites = () => api.get('/favorites');

Step 5 — Frontend Component + Route in App.js

jsximport FavoritesPage from './components/favorites/FavoritesPage';
// inside <Routes>
<Route path="/favorites" element={<FavoritesPage />} />

Step 6 — Test it! Start both servers and try the new feature.

✅ Tip: Always copy the style of an existing feature — the wishlist is almost identical! Look at user.controller.js → user.routes.js → the wishlist tab in UserDashboard.js.

13 Simple Glossary for Non-Technical Readers

API
URLs the frontend uses to ask the backend for data — a restaurant menu of requests.
Backend
The server-side code that processes requests and runs the logic.
Frontend
The code that draws pages in the browser (what users see).
Database
The storage where all data lives (MongoDB).
Model
A description of one data item (e.g., "a Dish has name, price, image").
Route / Endpoint
A specific URL + method (e.g., POST /api/cart/add).
Controller
The function that handles a request and decides what to do.
Middleware
Code that runs between the request and the controller (login check, uploads).
Token (JWT)
A digital login ticket proving who you are.
OTP
One-Time Password — a 6-digit code for password reset.
Mongoose
Helper library for talking to MongoDB from Node.js.
JSON
A text format for sending data between frontend and backend.
Socket / Real-time
Instant communication — no page refresh needed.
Redux
The app's shared "memory" (login, cart) available everywhere.
Component
A reusable UI piece (a button, a card, a page).
Hook
A React function that gives a component extra abilities.
Seeder / Script
A program that fills the database with sample data.
Deploy / Production
Putting the app on a real server for the public.
Repository (repo)
Your code folder tracked by Git/GitHub.
Commit
A saved snapshot of your code changes.
Push
Uploading your commits to GitHub.
